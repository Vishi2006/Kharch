# Kharch UPI Automation — Architecture & Implementation Document

## 1. System Overview & Cross-Platform Strategy (Option A)

Kharch is a personal expense management application designed for ≤10 known users. It operates as a local-first **Progressive Web App (PWA)** built with Next.js App Router (React 19, Tailwind CSS, Lucide icons, Recharts) and an Express.js + MongoDB backend deployed on Render, with the frontend hosted on Vercel.

### Option A: Universal PWA Core + Optional Android Companion

Because Apple’s iOS sandbox and Android’s security model handle third-party notification scraping differently, Kharch uses **Option A** to deliver cross-platform functionality without fragmented codebases:

#### Why Option A is the Optimal Cross-Platform Choice
1. **iOS (Apple) Reality**:
   - Apple’s operating system strictly forbids web apps and third-party native apps from reading notifications generated by other applications.
   - An APK file cannot execute on iOS.
   - **User Experience**: iPhone users install the PWA from Safari ("Add to Home Screen"). They get instant offline access, full dashboard analytics, manual expense entry, and the **Phase 1 QR Scan & Pay** workflow (`upi://pay` deep links directly trigger PhonePe, GPay, or Paytm installed on iOS, returning the user to Kharch to save the receipt).
2. **Android Reality**:
   - Android permits authorized background notification access via the system service `NotificationListenerService`.
   - **User Experience**: Android users install the same PWA. Inside **Settings**, they have a **"Download Android Auto-Sync Companion"** button. Installing this lightweight APK allows their device to capture transaction alerts in the background and pipe them into their Kharch Inbox automatically.

## 2. Phase-by-Phase Technical Implementation

### Phase 1 — QR Scan → UPI Payment → Result Capture (PWA)

* **Camera QR Scanner Component**:
  - Implemented in [`frontend/src/components/QRScanner.js`](file:///D:/coding/Kharch/frontend/src/components/QRScanner.js) using `html5-qrcode`.
  - Safely handles camera permissions, video aspect ratio, and tear-down upon unmount.
* **Defensive UPI URI Parser**:
  - Located in [`frontend/src/app/pay/page.js`](file:///D:/coding/Kharch/frontend/src/app/pay/page.js).
  - Defensive extraction of standard UPI parameters: `pa` (Payee VPA), `pn` (Payee Name), `am` (Amount), `cu` (Currency), and preserves `rawPayload`.
  - If critical fields are missing or malformed, falls back to manual edit fields without guessing.
* **Client-Side Persistence Before Intent**:
  - Uses `uuid` to generate a `paymentAttemptId` (UUID v4).
  - Persists record with status `PENDING` to IndexedDB using Dexie before triggering the deep link, ensuring survival if the mobile OS reloads or kills the PWA while the UPI app is focused.
* **Deep Link Trigger & Visibility Return**:
  - Triggers standard Android/iOS intent resolution: `window.location.href = upi://pay?pa=...&pn=...&am=...&cu=INR&tr=<paymentAttemptId>`.
  - Listens to `visibilitychange`, `window.focus`, and component mount on return.
  - Waits up to 15–20 seconds for payment callback parameters; if none are received, safely sets the attempt status to `UNKNOWN` (never assumes failure).
* **Backend Payment Attempt APIs**:
  - [`backend/models/PaymentAttempt.js`](file:///D:/coding/Kharch/backend/models/PaymentAttempt.js): schema indexing `paymentAttemptId`, `userId`, `amount`, `payeeVpa`, `payeeName`, and `status`.
  - [`backend/routes/paymentAttempts.js`](file:///D:/coding/Kharch/backend/routes/paymentAttempts.js): endpoints `POST /api/payment-attempts`, `GET /api/payment-attempts`, and `PUT /api/payment-attempts/:id`.

### Phase 2 — Android Companion App (Native Kotlin & Room)

Located in [`android/`](file:///D:/coding/Kharch/android/) as a standalone, lightweight Android project compiling with Gradle 8.11.1 and JDK 17.

* **Screen 1: Privacy Consent ([`ConsentActivity.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/ui/ConsentActivity.kt))**:
  - Runs before any permission request.
  - Configurable allowlist: PhonePe (`com.phonepe.app`), Google Pay (`com.google.android.apps.nbu.paisa.user`), Paytm (`net.one97.paytm`), BHIM (`in.org.npci.upiapp`), plus a dynamic input field to add bank package names.
  - Displays verbatim disclosure text:
    > *"Android grants access to all notifications at the OS level. This app immediately discards anything outside your selected list above — nothing outside it is stored or transmitted."*
  - Saves `ConsentRecord` to Room and syncs to backend `POST /api/consent`.
* **Screen 2: OEM Setup Wizard ([`OemWizardActivity.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/ui/OemWizardActivity.kt))**:
  - Detects `Build.MANUFACTURER` with explicit branching for **Xiaomi, Realme, Vivo, Oppo, Samsung**, and a generic fallback.
  - Buttons to launch OEM-specific autostart settings, trigger `Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, and open `dontkillmyapp.com/<manufacturer>`.
  - Starts [`KharchForegroundService.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/service/KharchForegroundService.kt) with persistent low-priority notification: *"Kharch is listening for transactions"*.
* **Screen 3: Health Check / Home ([`MainActivity.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/ui/MainActivity.kt))**:
  - Displays *"Last notification captured: X min/hours ago"*.
  - Live subsystem status cards: Notification Access, Battery Optimization, Foreground Service.
  - Warning banner for stale notifications or revoked permissions with a **"Re-check Permissions"** button.
* **Screen 4: Settings & Revocation ([`SettingsActivity.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/ui/SettingsActivity.kt))**:
  - Edit allowlist packages and server connection URL.
  - Persistent **"Revoke Access & Clear Data"** button: stops foreground service, opens OS settings to revoke notification listener permissions, calls backend `DELETE /consent` & `DELETE /my-data`, and clears all local Room SQLite tables.
* **Notification Listener Service ([`KharchNotificationListener.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/service/KharchNotificationListener.kt))**:
  - Extends `NotificationListenerService`.
  - Re-checks allowlist live from Room on every notification event; immediately discards unlisted packages.
  - Extracts timestamp, package name, title, and body.
* **Isolated Parser Modules ([`parser/`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/parser/))**:
  - Individual parsers: `PhonePeParser.kt`, `GPayParser.kt`, `PaytmParser.kt`, `BhimParser.kt`, and `ParserFactory.kt`.
  - Normalizes into `ParsedNotification { type: CREDIT|DEBIT, amount, counterparty, referenceId, timestamp, sourceApp, rawText, parseStatus }`.
  - Regex failures do not drop records; instead, they mark `parseStatus = "unparsed"` to allow manual categorization in the Inbox.
* **Local Storage (Room)**:
  - `NotificationEvent`: indexed on `idempotencyKey = SHA-256(timestamp_rounded_to_minute + "_" + amount + "_" + sourceApp + "_" + rawText)`. Duplicate inserts are ignored.
  - `SyncQueue`: tracks `PENDING → SYNCING → SYNCED` state with retry counters.

### Phase 3 — Sync Bridge (Companion → Backend)

* **Long-Lived Device Pairing**:
  - [`backend/models/DeviceToken.js`](file:///D:/coding/Kharch/backend/models/DeviceToken.js): Stores secure device tokens linked to user IDs.
  - PWA Settings ([`frontend/src/app/settings/page.js`](file:///D:/coding/Kharch/frontend/src/app/settings/page.js)) has a **"Pair Device"** button calling `POST /api/companion/token` and renders an SVG QR code using `qrcode`.
  - Android Settings ([`SettingsActivity.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/ui/SettingsActivity.kt)) provides **"📷 Scan PWA Pairing QR"** using ZXing to scan the screen and save the pairing token and server URL.
* **Idempotent Ingestion Endpoint**:
  - [`backend/routes/notifications.js`](file:///D:/coding/Kharch/backend/routes/notifications.js): `POST /api/notifications/sync`.
  - Authenticates via Bearer Device Token or JWT cookie.
  - Uses MongoDB `bulkWrite` with `$setOnInsert` and a unique index on `idempotencyKey` to guarantee deduplication.
* **Reliable Sync Triggers**:
  - [`android/app/src/main/java/com/kharch/companion/sync/SyncWorker.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/sync/SyncWorker.kt): Background `CoroutineWorker` that batches pending Room records and flushes to `/api/notifications/sync`.
  - [`android/app/src/main/java/com/kharch/companion/sync/SyncManager.kt`](file:///D:/coding/Kharch/android/app/src/main/java/com/kharch/companion/sync/SyncManager.kt):
    1. **Periodic WorkManager**: 15-minute scheduled sync respecting Android Doze mode constraints.
    2. **Network Callback**: `ConnectivityManager.NetworkCallback` triggers sync immediately upon internet restoration.
    3. **Foreground / Event Trigger**: Flushes immediately on `MainActivity.onResume()` and whenever a new payment notification arrives.
* **Direct APK Distribution**:
  - Backend route `GET /api/companion/download` in [`backend/routes/companion.js`](file:///D:/coding/Kharch/backend/routes/companion.js) serves `KharchCompanion.apk` directly to users via a one-click button in the PWA Settings.

### Phase 4 — Inbox + Matching Engine

* **Server-Side Matching Engine ([`backend/utils/matchingEngine.js`](file:///D:/coding/Kharch/backend/utils/matchingEngine.js))**:
  - Automatically evaluates incoming `NotificationEvent`s against open `PaymentAttempt`s based on direction, amount, time window (±5 mins), and counterparty token overlap.
  - **`HIGH` Confidence** *(Exact amount + timestamp within 2 minutes + counterparty match)*:
    - Auto-merges into a new `Transaction` in the user's default space.
    - Marks both `PaymentAttempt` as `SUCCESS` and `NotificationEvent` as `LINKED`.
  - **`MEDIUM` Confidence** *(Exact amount + timestamp within 5 minutes, without counterparty match)*:
    - Surfaces in the Inbox as a suggested match with side-by-side comparison.
  - **`LOW` Confidence / No Match**:
    - Appears as standalone Inbox alert needing manual categorization.
  - *Ledger Integrity Rule*: Never writes to the ledger without at least `HIGH` confidence or explicit user action.
* **Backend Inbox API ([`backend/routes/inbox.js`](file:///D:/coding/Kharch/backend/routes/inbox.js))**:
  - `GET /api/inbox`: returns `mediumMatches`, `unmatchedEvents`, and `unknownAttempts`.
  - `POST /api/inbox/accept-match`: accepts a medium suggestion, attaches space and category, and merges to a transaction.
  - `POST /api/inbox/convert`: converts standalone alert or unknown QR payment to a finalized transaction.
  - `POST /api/inbox/dismiss`: dismisses records from the inbox without ledger changes.
* **PWA Inbox UI ([`frontend/src/app/inbox/page.js`](file:///D:/coding/Kharch/frontend/src/app/inbox/page.js))**:
  - Navigation button with unread count in dashboard header.
  - "Possible Matches" tab with **Accept Match** and **Reject** buttons.
  - "Unmatched & Unknown" tab with **Convert to Transaction** modal and **Dismiss** actions.
  - Categorization modal to set Title, Space, and Expense Importance (Essential / Moderate / Low Value).
  - Empty state displaying *"Inbox Zero 🎉"*.

### Phase 5 — Offline-First PWA + Backend Wake-Up

* **Render Cold-Start Wake-Up ([`frontend/src/context/AppContext.js`](file:///D:/coding/Kharch/frontend/src/context/AppContext.js))**:
  - Non-blocking `fetch('/api/health', { keepalive: true })` ping on app launch.
  - Exponential backoff retry loop (2s, 4s, 8s, 16s... up to 60s total) for waking sleeping instances.
  - Sleek top pill in [`frontend/src/components/AppShell.js`](file:///D:/coding/Kharch/frontend/src/components/AppShell.js) displaying `Syncing with server...` without blocking UI interaction.
  - Automatically flushes offline mutations as soon as health responds 200 OK.
* **Dexie.js Local-First SWR Reads ([`frontend/src/utils/db.js`](file:///D:/coding/Kharch/frontend/src/utils/db.js))**:
  - Stores: `transactions`, `spaces`, `dashboardCache`, `paymentAttempts`, `notificationEvents`, and `pendingSync`.
  - User session, spaces, and dashboard metrics render instantly from IndexedDB cache on initial load.
  - Fresh metrics revalidate in the background (SWR pattern) and update IndexedDB and React state simultaneously.
* **Offline Writes & FIFO Queue ([`frontend/src/utils/syncQueue.js`](file:///D:/coding/Kharch/frontend/src/utils/syncQueue.js))**:
  - Manual transaction creation in [`frontend/src/app/add/page.js`](file:///D:/coding/Kharch/frontend/src/app/add/page.js) is fully unblocked when offline.
  - Mutations write to IndexedDB and queue in `pendingSync` with `status: 'offlineQueued'`.
  - Automatically flushes in FIFO order whenever `window.ononline` fires or the backend wake-up ping succeeds.
  - Visual status pill displays `{count} offline changes queued for sync`.

## 4. How to Run & Verify

### Running the Backend
```bash
cd D:\coding\Kharch\backend
npm install
npm run dev
# Starts on http://localhost:5000
# Health check: http://localhost:5000/api/health
```

### Running the Frontend (PWA)
```bash
cd D:\coding\Kharch\frontend
npm install
npm run dev
# Starts on http://localhost:3000
```

### Building the Android Companion APK
```bash
cd D:\coding\Kharch\android
gradlew.bat assembleDebug
# Generated output:
# D:\coding\Kharch\android\app\build\outputs\apk\debug\app-debug.apk
```

To install on a connected Android phone or emulator:
```bash
adb install -r "D:\coding\Kharch\android\app\build\outputs\apk\debug\app-debug.apk"
```
Or download directly from the PWA running on the phone by navigating to **Settings → Android Auto-Sync Companion → Download APK**.
